條件監控通知器：範例執行結果

這是範例：用虛構資料重播，讓程式跑一次後輸出的結果。這個工具還沒有在實際設備或手機上使用過。

虛構資料：3 台設備（OVEN-01、OVEN-02、PUMP-01），2026-11-02 08:00～10:00，每分鐘一筆，共 300 筆

OVEN-01 溫度與通知時間點

發出「溫度過高」發出「已恢復正常」條件又成立，但在 30 分鐘冷卻內，不通知

09:11～09:19 溫度在 200°C 上下來回跳了 5 次。如果每次超過都通知，9 分鐘內會收到 5 則「過熱」加 5 則「恢復」；實際只通知第一次和它的恢復。

對應的規則設定

rules:
  - id: oven_overheat
    target: "*"            # 所有設備
    message: 溫度過高
    level: critical
    notify_recover: true   # 恢復正常也通知
    all:
      - { field: temp, op: ">=", value: 200 }

  - id: pump_pressure_low
    target: PUMP-01
    message: 壓力跌破下限
    level: warning
    all:
      - { field: pressure, op: cross_below, value: 0.8 }

其他設定

設定範例值作用
冷卻時間30 分鐘同一條規則通知後，多久內不再通知
資料中斷10 分鐘某台設備超過 10 分鐘沒有新資料就通知（OVEN-02 在 08:59 之後停止回報）
監控時段週一～五 08:00～20:00下班時間不檢查資料中斷，避免半夜被吵醒
來源失敗連續 3 次檔案讀不到、API 連不上，連續失敗才通知，恢復後再通知一次
